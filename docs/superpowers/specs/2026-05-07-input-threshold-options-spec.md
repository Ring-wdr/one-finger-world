# 입력 임계값 옵션 노출 스펙

Date: 2026-05-07

## 목적

이 문서는 한 손가락 입력 인식기(`src/lib/game/input/InputController.ts`)에 박혀 있는 임계값 상수들을 **사용자에게 노출할 옵션**과 **개발자 전용 튜닝값**으로 분리해 잠근다. 토대 스펙(`docs/superpowers/specs/2026-05-07-narrative-and-progression-foundation-design.md`) §범위 외가 "광범위한 콘트롤 옵션은 시즌 1 범위 외이며, 입력 임계값 튜닝만 노출"이라 잠근 그 한 줄을 본 문서가 정량화한다. 챕터 1 페이싱 스펙(`docs/superpowers/specs/2026-05-07-chapter-1-encounter-pacing.md`)이 잠근 4분 시간 도전·30 이하 피해 도전·8콤보 콤보 도전을 노출 옵션의 모든 조합에서 달성 가능하게 만드는 것이 본 문서의 잠금 조건이다.

이 문서가 잠그지 않는 것: 햅틱 강도·진동·사운드 큐(별도 접근성 문서로 위임), 카메라 풀백·시야 범위(챕터 1 페이싱 스펙 §4), 콤보 스킬 트리(콤보 스킬 트리 스펙).

참조:

## 1. 현 프로토타입 임계값 목록

`InputController.ts`의 기본 임계값 묶음과 입력 베이스라인 문서 §Input Model의 제스처 규칙에서 읽어낸 임계값은 총 **여섯 개**다. 다섯 개는 임계값 묶음에 명시 상수로 들어 있고, 한 개("드래그 보유에 의한 런 승격 시간")는 입력 베이스라인 문서가 제스처 규칙에 잠근 값이지만 현재 인식기에는 거리 기반 런 승격(72 픽셀)만 구현되어 있다 — 본 문서는 **시간 기반 런 승격을 베이스라인 정의대로 임계값 한 줄**로 함께 다룬다.

| 임계값 이름 | 현재 값 | 의미 | 영향 받는 제스처 |
|---|---|---|---|
| 탭 인식 지속 시간 | 180 밀리초 | 누름에서 뗌까지의 시간이 이 값 이하이고 동시에 이동 거리가 드래그 시작 거리 미만일 때만 탭이 공격으로 인식된다. 더 길게 누르면 탭이 무효가 되고 콤보가 진행되지 않는다 | 탭 → 공격, 공격 콤보 단계 진행 |
| 드래그 시작 거리 | 14 픽셀 | 누름 지점에서 손가락이 이 거리만큼 벗어나는 순간부터 이동 모드로 들어간다. 그 거리 미만에서 떼면 손가락의 미세한 흔들림이 탭으로 처리된다 | 탭 vs 드래그 분기, 이동 시작 |
| 런 승격 거리 | 72 픽셀 | 누름 지점 기준 손가락이 이 거리 이상으로 벌어져 있는 동안 이동 모드가 걷기에서 달리기로 올라간다. 거리가 줄면 다시 걷기로 내려간다 | 걷기 → 달리기 승격 |
| 런 보유 승격 시간 | 450 밀리초 | 입력 베이스라인 문서가 잠근 또 다른 런 승격 조건. 드래그 시작 후 이 시간이 지나면 거리와 무관하게 달리기로 승격. 현재 인식기 코드에는 미구현이며 본 문서는 이 값을 향후 구현 시 탑재될 임계값으로 함께 분류한다 | 걷기 → 달리기 승격 (시간축) |
| 빠른 드래그 속도 | 0.9 픽셀 / 밀리초 | 드래그 종료 시점의 평균 속도가 이 값 이상이면 그 드래그 한 번을 대시 후보로 등록한다. 속도가 모자라면 단순히 정지로 마무리된다 | 빠른 드래그 인식, 대시 후보 등록 |
| 대시 더블탭 윈도 | 320 밀리초 | 빠른 드래그 한 번이 등록된 뒤 이 시간 이내에 두 번째 빠른 드래그가 들어와야 대시·회피 제스처가 발동된다. 시간이 지나면 후보가 폐기된다 | 두 번 빠른 드래그 → 대시·회피 |

여섯 개 임계값은 모두 한 손가락 제스처 인식기의 경계 조건이다. 어느 하나가 한쪽으로 너무 치우치면 다른 제스처를 빨아먹는다(예: 탭 인식 지속 시간이 너무 길면 짧은 누름이 다 탭이 되어 드래그가 시작되지 않음).

## 2. 노출 분류

여섯 개 임계값을 **노출** 또는 **비노출**로 분류한다. 노출 총 개수는 **3개**로 잠근다(토대 스펙의 한 손가락 단순함 가드와 본 계획의 "노출 ≤ 3" 제한 합치).

| 임계값 이름 | 분류 | 사유 |
|---|---|---|
| 탭 인식 지속 시간 | **노출** | 손가락 떨림·근력 약화·노안 사용자가 가장 많이 부딪히는 경계. 짧으면 탭이 매번 무효화되고 길면 드래그 의도가 탭으로 처리된다. 사용자별 손가락 박자 차이가 가장 직접적으로 드러나는 임계값이라 노출 1순위 |
| 드래그 시작 거리 | **노출** | 미세 떨림이 있는 사용자, 큰 손가락(접지 면적 큰) 사용자가 가장 많이 부딪히는 경계. 작으면 의도하지 않은 드래그가 빈번하고 크면 작은 의도 드래그가 무시된다. 노출 2순위 |
| 런 승격 거리 | 비노출 | 사용자에 따라 화면 절반을 가로질러야 달리기 시키는 사람과 손바닥만 움직여 달리기 시키는 사람의 욕구가 갈리지만, 이 값을 노출하면 달리기 도달 시간이 별점 시간 도전(4분)과 직접 충돌해 밸런스 가드가 무너진다. 개발 내부에서 카메라 거리·룸 가로 폭과 함께 튜닝 |
| 런 보유 승격 시간 | 비노출 | 동일 사유. 사용자가 이 값을 줄이면 즉발 달리기가 가능해져 페이싱 가드가 깨진다. 거리 기반 승격이 이미 거리로 동일 학습을 흡수하므로 시간축은 내부 튜닝에 둠 |
| 빠른 드래그 속도 | **노출** | 한 손 큰 손가락·근력 약화 사용자가 대시·회피 제스처에서 가장 많이 좌절하는 경계. 너무 빠르면 평소 드래그가 다 빠른 드래그로 잡혀 의도하지 않은 대시가 발동되고, 너무 느리면 회피 학습 슬롯(작은 수호자 텔레그래프)에서 회피가 안 나간다. 노출 3순위 |
| 대시 더블탭 윈도 | 비노출 | 두 번째 빠른 드래그까지의 허용 시간은 사용자별 차이가 비교적 작고, 노출하면 빠른 드래그 속도와의 결합으로 의도하지 않은 대시가 폭발할 수 있다. 빠른 드래그 속도 한 축만 노출하고 더블탭 윈도는 내부 튜닝으로 고정 |

**노출 합계 3개** (탭 인식 지속 시간 / 드래그 시작 거리 / 빠른 드래그 속도). 비노출 3개(런 승격 거리 / 런 보유 승격 시간 / 대시 더블탭 윈도). 총 6개 모두 분류됨.

## 3. 노출 옵션 UI 명세

세 노출 옵션의 사용자 표시 한국어 옵션명·UI 형태·표시 단위·범위·설정 화면 한 줄 설명. UI는 별도 도면 없이 프로즈로 묘사한다.

### 3.1 옵션 표

| 옵션명 (사용자 표시) | UI 형태 | 표시 단위 | 최소 | 기본 | 최대 | 한 줄 설명문 |
|---|---|---|---|---|---|---|
| 탭 인식 시간 | 슬라이더 (3개의 프리셋 마커가 슬라이더 위에 점으로 보이며, 슬라이더는 마커 사이도 자유롭게 이동) | 밀리초 | 120 | 180 | 280 | "탭으로 공격을 내려면 손가락을 얼마나 짧게 떼야 하는지를 정합니다. 길게 잡을수록 느리게 떼도 공격이 나갑니다." |
| 드래그 시작 거리 | 슬라이더 (동일 프리셋 마커 표기) | 픽셀 | 8 | 14 | 24 | "손가락이 얼마나 움직여야 이동이 시작되는지를 정합니다. 작게 잡을수록 작은 움직임에 반응하고, 크게 잡을수록 손가락 떨림에 둔감해집니다." |
| 대시 빠르기 | 슬라이더 (동일 프리셋 마커 표기) | 픽셀 / 밀리초 (소수 첫째자리까지 표시) | 0.6 | 0.9 | 1.2 | "손가락을 얼마나 빨리 그어야 대시·회피가 나가는지를 정합니다. 작게 잡을수록 천천히 그어도 회피가 나가고, 크게 잡으면 빠르게 그어야만 발동합니다." |

### 3.2 프리셋 묶음

세 옵션은 따로따로도 조정 가능하지만, 사용자가 한 번에 셋을 한 무드로 맞추고 싶을 때 쓸 수 있도록 화면 상단에 프리셋 버튼 세 개를 둔다. 프리셋을 누르면 세 슬라이더가 동시에 해당 값으로 점프한다(슬라이더의 마커 점이 프리셋 위치를 가리킨다).

| 프리셋 이름 | 탭 인식 시간 | 드래그 시작 거리 | 대시 빠르기 | 대상 사용자 |
|---|---|---|---|---|
| 편안 | 240 밀리초 | 20 픽셀 | 0.7 픽셀 / 밀리초 | 느리게 떼는 사용자, 미세 떨림이 있는 사용자, 회피 박자가 한 박자 늦은 사용자 |
| 표준 | 180 밀리초 | 14 픽셀 | 0.9 픽셀 / 밀리초 | 베이스라인. 새 플레이어의 첫 진입 |
| 빠름 | 140 밀리초 | 10 픽셀 | 1.1 픽셀 / 밀리초 | 빠르게 떼고 작은 드래그를 즐기는 숙련 사용자, 콤보·회피의 즉시성을 우선하는 사용자 |

세 프리셋 모두 §6 밸런스 가드를 통과해야 한다(검증은 §6).

### 3.3 UI 프로즈 묘사

설정 화면의 "입력 임계값" 절은 옵션 화면 안의 한 페이지로 들어간다. 페이지 상단에 프리셋 버튼 세 개("편안", "표준", "빠름")가 가로로 나열되고, 그 아래 세 슬라이더가 세로로 쌓인다. 각 슬라이더는 위쪽에 옵션명·현재 값(단위 포함)·작은 정보 아이콘이 한 줄로 보이고, 정보 아이콘을 누르면 해당 슬라이더의 한 줄 설명문이 펼쳐진다. 슬라이더는 좌측이 최솟값, 우측이 최댓값이며, 표준 위치에 진한 점이, 편안·빠름 위치에 옅은 점이 마커로 그려져 있어 프리셋이 어디로 잡히는지 슬라이더 위에서도 보인다. 페이지 하단에 "기본값으로 되돌리기" 텍스트 링크가 있으며, 누르면 세 슬라이더가 표준 프리셋으로 점프한다.

페이지 안에서는 어떤 시각도 슬라이더 끝값을 무시하지 못한다 — 슬라이더는 최소·최대 사이로 클램프된다. 사용자가 옵션 페이지를 빠져나갈 때 변경 사항은 즉시 저장되며 별도 확인 모달은 없다(§5 동작 보장 정책의 일부).

## 4. 접근성 메모

세 부류의 사용자가 입력 임계값 옵션을 통해 케어된다.

**느린 탭 사용자** — 탭 박자가 한 박자 늦은 사용자(노안·손가락 근력 약화·관절염)는 표준 180 밀리초에서 탭 공격이 빈번히 무효화된다. **편안 프리셋**의 탭 인식 시간 240 밀리초가 이 사용자를 케어한다. 또한 옵션 슬라이더로 280 밀리초까지 더 늘릴 수 있어, 표준에서 80~100 밀리초 더 느린 박자도 탭으로 인식된다. 280 밀리초 상한은 §6 밸런스 가드의 콤보 도전(보스에게 8콤보 한 번)에서 콤보 진행이 끊기지 않는 라인을 기준으로 잡혔다.

**미세 떨림 사용자** — 손가락 끝의 미세 떨림(파킨슨 초기·노안·차량 진동 환경)이 있는 사용자는 표준 14 픽셀에서 의도하지 않은 드래그가 빈번해 탭이 잘 안 잡힌다. **편안 프리셋**의 드래그 시작 거리 20 픽셀이 이 사용자를 케어한다. 슬라이더로 24 픽셀까지 더 늘릴 수 있다. 24 픽셀 상한은 §6 밸런스 가드의 시간 도전(4분 클리어)에서 의도 드래그까지 무시되어 페이싱이 깨지지 않는 라인.

**한 손 큰 손가락 사용자** — 한 손으로 큰 손가락을 쓰는 사용자(엄지 조작·접지 면적이 큰 사용자)는 빠른 드래그를 자기 의지대로 내기 어렵다. 손바닥이 함께 따라가 평균 속도가 떨어지기 때문이다. **편안 프리셋**의 대시 빠르기 0.7 픽셀 / 밀리초가 이 사용자를 케어한다. 슬라이더로 0.6 픽셀 / 밀리초까지 더 낮출 수 있다. 0.6 픽셀 / 밀리초 하한은 §6 밸런스 가드에서 평소 걷기 드래그가 모두 대시로 빨려들어가지 않는 라인.

세 프리셋의 시나리오 매핑:

- **편안** ↔ 위 세 부류 모두. 한 프리셋으로 세 부류를 동시 케어한다.
- **표준** ↔ 새 플레이어의 첫 진입. 챕터 1 학습 슬라이스의 모든 텔레그래프·콤보 박자가 이 값에 맞춰 잠겼다(챕터 1 페이싱 스펙 §5 표준 플레이 가정).
- **빠름** ↔ 콤보·회피의 즉시성을 우선하는 숙련 사용자. 별점 도전 4분 시간을 노린 빠른 플레이(페이싱 스펙 §5의 약 3:30 라인)에서 즉시성이 한 단 더 살아남.

## 5. 동작 보장 정책

옵션 변경 시 입력 인식기의 동작은 **다음 한 가지 정책**으로 잠근다.

**진행 중 제스처 즉시 취소 후 새 임계값 적용.**

사용자가 옵션 페이지에서 슬라이더를 움직이거나 프리셋을 누르는 순간, 인식기는 활성 포인터가 있다면 그 포인터를 `pointercancel`과 동일한 경로로 종료시키고(현 인식기의 취소 처리 경로를 그대로 탄다), 활성 콤보·대시 후보·드래그 모드를 모두 초기화한 뒤 새 임계값을 다음 누름부터 즉시 사용한다.

이 정책의 근거:

- 옵션 페이지는 게임 플레이 중에는 열리지 않는 것이 토대 스펙·베이스라인의 가드다. 옵션을 여는 시점은 보통 메뉴·휴식 상태이므로 진행 중 제스처가 있을 가능성은 낮다. 그러나 모달이 활성된 상태에서 손가락이 캔버스에 닿아 있다가 메뉴로 빠져나가는 경우(컨텍스트 전환), 활성 포인터가 남을 수 있다 — 이 잔여 포인터가 새 임계값을 갖고 다시 평가되면 사용자가 이해할 수 없는 제스처(예: 옛 임계값 기준의 드래그가 새 임계값에서 빠른 드래그로 분류)가 튀어나온다.
- "활성 콘텐츠 종료 시까지 지연 적용"을 선택할 수도 있었지만, 그 정책은 사용자가 슬라이더를 움직였을 때 즉각적인 피드백이 없어 "값이 적용된 건지 안 된 건지" 확신을 잃게 만든다. 본 프로토타입은 한 손가락 단순함을 우선하므로 즉시 적용을 택한다.
- "진행 중 제스처 즉시 취소"는 현 인식기가 이미 `pointercancel`·`lostpointercapture` 경로에서 사용하는 동일한 정리 시퀀스를 재사용한다 — 새 정리 경로를 추가하지 않는다.

옵션 변경의 저장은 옵션 페이지를 빠져나갈 때 한 번 발생한다(세이브 모델 스펙 `docs/superpowers/specs/2026-05-07-save-and-progression-model.md`의 저장 트리거 정책에 따라 추후 잠긴다). 다음 앱 실행 시 마지막 저장값으로 복구된다.

## 6. 밸런스 가드

노출 옵션의 극단값에서도 챕터 1 별점 도전 세 개가 모두 달성 가능한지 검증한다. 챕터 1 별점 도전은 토대 스펙 §챕터 1 별점 도전과 챕터 1 페이싱 스펙 §5·§6에서 잠겼다 — **시간 4분 이내, 누적 피해 30 이하, 보스에게 8콤보 이상 한 번**.

극단 조합은 두 끝(편안의 모든 슬라이더가 가장 케어 쪽 끝까지 / 빠름의 모든 슬라이더가 가장 즉시성 쪽 끝까지)을 잡는다.

**편안 극단 (탭 280 밀리초 / 드래그 시작 24 픽셀 / 대시 0.6 픽셀 / 밀리초)**: 시간 도전은 페이싱 스펙 §5의 표준 플레이 240초 합산 위로 약 8~12초가 더 붙는다 — 탭 박자 둔감·드래그 시작 둔감으로 콤보 사이클당 약 0.3~0.5초가 늘어나기 때문. 챕터 1 잡몹 콤보 사이클이 약 8회(조우 1·2 합산), 보스 페이즈 1·2의 콤보 합이 약 10회로 잡으면 약 0.3~0.5 × 18 ≈ 5~9초. 합산 245~252초로 4분 경계에서 살짝 넘어갈 수 있다. 그러나 빠른 플레이 라인(§5의 약 3:30 = 210초)은 이 극단에서도 약 218~225초로 4분 안에 들어온다. **시간 도전 통과 가능**(빠른 플레이 라인). 피해 도전은 더 둔감한 임계값이 회피 박자를 늦추지 않는다(회피는 빠른 드래그로 발동되므로 대시 0.6 픽셀 / 밀리초가 회피를 더 쉽게 발동시킨다 — 작은 수호자 텔레그래프 회피가 오히려 안전해짐). 누적 피해 0~5(완벽~표준 §6.1)이 그대로 유지되어 보스 25와 합산 25~30. **피해 도전 통과 가능**(표준 라인 끝자락). 콤보 도전은 탭 박자 280 밀리초가 콤보 단계 진행을 깨지 않는지가 핵심 — 탭 인식이 280 밀리초 안에 들어오면 그대로 콤보 단계가 올라가므로, 탭 자체가 무효화되지 않는 한 8콤보가 가능하다. 280 밀리초는 통상 인간 탭 박자(150~250 밀리초)의 상한 너머이므로 거의 모든 탭이 인식된다. **콤보 도전 통과 가능**.

**빠름 극단 (탭 120 밀리초 / 드래그 시작 8 픽셀 / 대시 1.2 픽셀 / 밀리초)**: 시간 도전은 페이싱 스펙 §5의 빠른 플레이 라인 약 210초가 약 200~205초로 줄어든다(콤보 사이클당 짧은 박자 절약). **시간 도전 여유 통과**. 피해 도전은 대시 1.2 픽셀 / 밀리초가 회피를 까다롭게 만든다 — 평소 드래그 속도가 1.2 픽셀 / 밀리초에 닿지 않으면 회피 발동이 늦거나 실패한다. 그러나 §6.1의 표준 플레이는 회피 1회 늦음을 허용하고 그 결과가 누적 12 → 보스 25와 합산 37(별점 미달). 빠름 극단은 이 회피 박자를 더 까다롭게 하므로 **별점 통과는 작은 수호자 회피까지 모두 성공한 표준 플레이 끝자락에서만 가능**(피해 5 + 보스 25 = 30, 간신히 통과). 통과 가능성 자체는 살아있다. **피해 도전 통과 가능**(끝자락 라인). 콤보 도전은 탭 박자 120 밀리초가 짧은 사용자에게 까다롭다 — 손가락이 120 밀리초 안에 떼지지 않으면 탭이 무효화되어 콤보가 끊긴다. 그러나 사용자가 이 옵션을 일부러 선택한 시점은 본인 박자가 120 밀리초 안에 들어온다는 자각이 있는 경우다. 또한 8콤보는 보스에게 한 번만 달성하면 되므로 페이즈 1의 한 사이클(50초) 안에 한 번만 매끄럽게 가면 된다 — 120 밀리초 박자에 익숙한 사용자라면 충분히 가능. **콤보 도전 통과 가능**.

세 극단 조합 모두 별점 도전 세 개를 통과 가능 라인에 두었다. 단, 편안 극단에서 시간 도전은 표준 플레이가 아닌 빠른 플레이 라인에서만 통과 — 이는 의도된 트레이드오프이며 토대 스펙의 "별점은 학습 슬라이스 끝자락에서 통과"와 합치한다. **세 별점 도전 모두 모든 노출 옵션 조합에서 달성 가능**.

## 7. 범위 외

이 문서가 명시적으로 다루지 않는 항목.

- **햅틱 강도** — 진동 피드백의 세기·길이 조정. 별도 접근성 문서로 위임.
- **진동** — 입력 피드백 외 게임 이벤트(피격·콤보 마무리·보스 처치)의 진동 신호. 별도 접근성 문서.
- **사운드 큐** — 텔레그래프·콤보 단계의 청각 신호. 음악·음향 디렉션 문서.
- **카메라 풀백·시야 범위 사용자 옵션** — 카메라 거리 자체는 챕터 1 페이싱 스펙 §4와 입력 베이스라인이 잠갔으며 사용자에게 노출하지 않는다는 가드도 베이스라인이 잠갔다.
- **옵션 페이지 시각 디자인** — 폰트·색·여백·아이콘 모양은 별도 UI 디자인 문서.
- **로컬라이제이션** — 옵션명·설명문의 다국어 번역. 별도 로컬라이제이션 계획.
- **콤보 입력 가드** — 콤보 단계 간 최소 박자 강제 등 별도 가드. 콤보 스킬 트리 스펙(`docs/superpowers/specs/2026-05-07-combo-skill-tree-spec.md`)이 다룬다.
- **자동 회피 보조 / 자동 조준 보조** — 한 손가락 입력 보조 기능. 시즌 1 범위 외.
- **게임패드·키보드 매핑** — 토대 스펙의 입력 모델 가드 외. 시즌 1 범위 외.

## 8. 자체 검토

- **여섯 개 임계값 모두 분류**: 탭 인식 지속 시간(노출), 드래그 시작 거리(노출), 런 승격 거리(비노출), 런 보유 승격 시간(비노출), 빠른 드래그 속도(노출), 대시 더블탭 윈도(비노출). 노출 3 + 비노출 3 = 6.
- **노출 옵션 ≤ 3**: 정확히 3개. 토대 스펙·계획의 한 손가락 단순함 가드 합치.
- **모든 노출 옵션의 min·default·max 범위 명시**: 탭 인식 시간 120/180/280 밀리초, 드래그 시작 거리 8/14/24 픽셀, 대시 빠르기 0.6/0.9/1.2 픽셀 / 밀리초.
- **밸런스 가드 별점 3개 검증**: 시간 4분, 누적 피해 30 이하, 보스 8콤보. 편안 극단·빠름 극단 두 조합에서 모두 통과 가능 라인.
- **임계값 한국어 의미어 표기**: 영문 식별자(`TAP_DURATION_MS` 등) 사용 없음. 한국어 의미어("탭 인식 지속 시간" 등)만 사용.
- **사용자 노출 옵션 한국어 옵션명 명시**: "탭 인식 시간", "드래그 시작 거리", "대시 빠르기" 세 개.
- **코드 0건**: 코드 블록·함수 시그니처 사용 없음. 임계값 표기는 텍스트 단위로만(예: "180 밀리초", "14 픽셀").
- **UI 프로즈 묘사**: 별도 도면·이미지 없이 §3.3에서 프로즈로 옵션 페이지 레이아웃 묘사.
- **동작 보장 정책 단일 선택**: 진행 중 제스처 즉시 취소 후 새 임계값 적용. 단일 정책으로 잠금.
- **접근성 세 부류 케어 + 프리셋 매핑**: 느린 탭·미세 떨림·한 손 큰 손가락 세 부류 모두 편안 프리셋이 케어. 표준·빠름 프리셋의 매핑 시나리오도 명시.
- **범위 외 명시**: 햅틱·진동·사운드·카메라·UI 시각·로컬라이제이션 등 본 문서가 다루지 않는 항목을 §7에 분리 위임.
