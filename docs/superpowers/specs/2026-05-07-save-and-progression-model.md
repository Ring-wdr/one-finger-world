# 세이브·진행 동기화 데이터 모델 (One-Finger World, 시즌 1)

Date: 2026-05-07

## 목적

토대 스펙(`docs/superpowers/specs/2026-05-07-narrative-and-progression-foundation-design.md`), 콤보 스킬 트리 스펙(`docs/superpowers/specs/2026-05-07-combo-skill-tree-spec.md`), 시즌 1 곡선(`docs/superpowers/specs/2026-05-07-season-1-arc-outline.md`), 챕터 1 페이싱(`docs/superpowers/specs/2026-05-07-chapter-1-encounter-pacing.md`)이 잠근 어휘 위에서, 잊혀진 자의 진행이 어떻게 디스크에 기록되고 어떻게 다시 손에 돌아오는지를 정의한다.

이 문서는 데이터 모델의 **모양**만을 잠근다. 실제 직렬화 형식·파일 경로·암호화 정책은 코드 구현 단계에서 결정된다. 본 문서는 코드·의사 코드·JSON 스니펫·함수 시그니처를 일절 포함하지 않으며, 모든 정의는 산문과 마크다운 표로만 기술한다.

토대 어휘는 그대로 따른다 — 잊혀진 자 / 콤보 / 회피 / 신성 / 추모자 / 수호자 / 기억의 화신 / 외곽 / 내부 / 핵 / 별점 / SP. "스타"·"점수"·"포인트" 같은 동의어는 사용하지 않는다.

---

## 1. 저장 데이터 스키마

저장 데이터는 다음 필드 집합으로 구성된다. 모든 필드는 한 명의 잊혀진 자(=한 세이브 슬롯)에 종속된다. 시즌 1은 단일 슬롯만 운용한다(다중 캐릭터 슬롯은 시즌 2 이후의 결정).

| 필드명 | 의미 | 타입 (텍스트로) | 예시 값 |
|---|---|---|---|
| 챕터 진행 상태 | 본편 9개·사이드 6개 각각의 클리어 여부. 챕터 ID에서 boolean으로의 매핑. 시즌 1에서는 본편 9개 키와 사이드 6개 키 — 도합 15개의 키가 항상 존재한다 | 식별자에서 boolean으로의 매핑 | 본편 1·2 클리어, 사이드 1 클리어, 그 외 미클리어 |
| 챕터별 별점 3개 | 본편 챕터마다 시간·피해·콤보 세 별점의 획득 여부. 사이드 챕터는 별점 1개(시간 또는 피해 중 하나) 슬롯만 사용한다 | 챕터 ID에서 별점 종류로의 boolean 집합 매핑 | 본편 1: 시간 획득·피해 획득·콤보 미획득 / 사이드 1: 시간 획득 |
| SP 합계 | 잊혀진 자가 시즌을 통틀어 누적한 SP 총량. 트리 노드 구매로 차감되지 않는다 — "누적 SP"와 "사용 SP"는 분리된다(§4) | 0 이상의 정수 | 27 |
| 사용 SP | 현재 트리 노드 보유에 의해 차감된 SP 총합. 누적 SP - 사용 SP = 보유 SP. 리셋 시 사용 SP만 0으로 돌아간다 | 0 이상의 정수 | 12 |
| 보유 스킬 노드 집합 | 콤보·회피·신성 가지에서 현재 구매된 노드의 식별자 집합. 각 가지의 단일 선형 사슬이므로 집합은 곧 가지별 도달 깊이와 동치다. 트리 리셋 시 비워진다 | 노드 식별자의 집합 | {콤보 가지 노드 1, 콤보 가지 노드 2, 회피 가지 노드 1} |
| 게이팅 보스 클리어 플래그 | 챕터 5·7·9의 게이팅 보스(향의 수호자·봉인의 화신·기억의 화신)를 한 번이라도 통과했는가에 대한 boolean 플래그 3개. 트리 리셋 후에도 보존된다 | boolean 3개 | 챕터 5 통과·챕터 7 미통과·챕터 9 미통과 |
| 사이드 클리어 플래그 | 사이드 6개 각각의 클리어 여부. 챕터 진행 상태 필드와 중복으로 보일 수 있으나, 사이드는 도전 보너스(+1 SP) 별점 슬롯이 1개뿐이므로 본편과 분리된 형태로 기록된다 | 사이드 ID에서 boolean으로의 매핑 | 사이드 1 클리어, 사이드 2 미클리어, ... |
| 일회성 환영 플래그 | 인터루드·튜토리얼 환영(예: 챕터 1 첫 인터루드 일러스트, 다이어제틱 튜토리얼 텍스트 5줄, 챕터 3 외곽→내부 전이 인터루드 등)을 한 번이라도 시청했는가의 플래그 묶음 | 환영 ID에서 boolean으로의 매핑 | 챕터 1 시작 인터루드 시청, 다이어제틱 텍스트 5줄 모두 시청 |
| 트리 리셋 횟수 누적 | 트리를 리셋한 누적 횟수. 리셋 자체는 무료이지만 분석 목적으로 카운트만 유지한다 | 0 이상의 정수 | 2 |
| 일회성 사망 통계 (옵션) | 챕터별 누적 사망 횟수. 별점·진행에 영향을 주지 않으며, 분석·결과 화면 인사말 변형에만 사용된다. 옵션 — 시즌 1에서는 수집 동의를 받지 않으면 비활성화 가능 | 챕터 ID에서 0 이상의 정수로의 매핑 또는 비활성 표시 | 본편 1: 사망 3회 / 본편 2: 사망 1회 |
| 입력 임계값 사용자 옵션 값 | 입력 임계값 옵션 스펙(`docs/superpowers/specs/2026-05-07-input-threshold-options-spec.md`)이 노출하는 사용자 조정 옵션의 현재 값. 옵션 미설정 시 디폴트로 간주 | 옵션 키에서 정수 또는 프리셋 식별자로의 매핑 | 탭 임계값 프리셋: "표준" / 드래그 임계값 프리셋: "느슨함" |
| 마지막 진입 노드 | 잊혀진 자가 마지막으로 진입한 지도 노드(=챕터)의 식별자 또는 "지도" 표시. 앱 재진입 시 이 값이 복귀 지점을 결정(§3) | 챕터 식별자 또는 "지도" 표시 | "지도" / "본편 5" |
| 앱 버전 | 세이브가 작성된 시점의 앱 버전 문자열. 마이그레이션 정책(§6)에서 호환 검사에 사용 | 버전 문자열 | "0.4.1" |
| 스키마 버전 | 세이브 스키마 자체의 정수 버전. 앱 버전과 독립적으로 증가한다(스키마가 바뀌지 않는 패치 릴리스에서는 그대로) | 1 이상의 정수 | 1 |

필드 수는 14개로, 토대 스펙이 다루는 모든 진행 축(챕터·별점·SP·트리·게이팅·사이드·환영·옵션·복귀)을 덮는다. 14개 모두 의미와 타입과 예시 값이 채워졌다.

추가 메모:

- "보유 스킬 노드 집합"은 단일 선형 사슬이라는 트리 구조 가정 위에서 가지별 도달 깊이로도 표현 가능하지만, 시즌 2 이후 분기 노드가 도입될 가능성을 열어 두기 위해 처음부터 집합으로 기록한다.
- "챕터별 별점 3개"는 본편의 시간·피해·콤보 세 슬롯을 키로 두며, 사이드의 단일 슬롯은 같은 매핑 안에 "시간 또는 피해 중 하나"의 키 한 개만 두는 변형으로 통일한다. 공간 절약보다 인덱싱 일관성을 우선한다.
- "일회성 사망 통계"는 옵션이며 비활성화 시 전체 필드가 부재한다. 다른 필드는 모두 항상 존재한다(부재 시 기본값 적용).
- "마지막 진입 노드"가 "지도"인 상태는 잊혀진 자가 챕터에 진입하지 않고 지도 화면에서 앱을 닫은 상태를 가리킨다.

## 2. 저장 트리거 목록

저장은 다음 트리거에서 발생한다. 각 트리거는 동일한 세이브 객체를 디스크에 기록하지만(즉 부분 갱신이 아니라 전체 기록), 각 트리거가 "어떤 필드를 의미적으로 갱신하는가"를 본 절이 명시한다.

- **챕터 클리어**: 챕터 진행 상태(또는 사이드 클리어 플래그)에 해당 챕터를 추가, SP 합계에 본편 1 SP/사이드 1 SP를 더함, 마지막 진입 노드를 "지도"로 환원, 게이팅 챕터(5·7·9)인 경우 게이팅 보스 클리어 플래그 갱신, 챕터 종료 인터루드 시청 후 일회성 환영 플래그 갱신.
- **별점 갱신**: 챕터별 별점 3개의 해당 슬롯을 boolean 참으로 전환(이미 참이면 변경 없음), 갱신된 별점 수만큼 SP 합계에 가산. 본 트리거는 챕터 클리어 트리거와 거의 동시에 발생하지만, 재도전으로 별점만 추가 획득한 경우에는 단독으로 발생한다.
- **트리 노드 구매**: 보유 스킬 노드 집합에 해당 노드 식별자 추가, 사용 SP를 노드 비용만큼 증가. 트리 화면(=지도 화면 위 모달)에서만 발생.
- **트리 리셋**: 보유 스킬 노드 집합을 비움, 사용 SP를 0으로 환원, 트리 리셋 횟수 누적을 1 증가. 누적 SP·별점·챕터 진행 상태·게이팅 보스 클리어 플래그는 영향받지 않는다(§4).
- **입력 옵션 변경**: 입력 임계값 사용자 옵션 값 갱신. 한 옵션 변경마다 즉시 발생하며, 다음 챕터 진입 전에 디스크 반영을 보장.
- **일회성 환영 시청**: 인터루드·다이어제틱 텍스트·튜토리얼 환영을 본 직후 해당 환영의 일회성 환영 플래그를 참으로 전환. 같은 환영을 두 번째 본 경우에는 트리거가 발생하지 않는다.
- **앱 백그라운드 진입**: OS 차원에서 앱이 백그라운드로 들어가는 직전, 마지막 진입 노드를 현재 위치로 갱신하고 전체 세이브를 한 번 기록한다. 이 트리거는 막힌 챕터에서 빠져나오기 전이라도 항상 발생한다.
- **사망 모달의 "나가기" 선택**: 마지막 진입 노드를 "지도"로 환원하고, 일회성 사망 통계가 활성화되어 있으면 해당 챕터의 사망 카운트를 1 증가. 별점·SP·트리·진행 상태에는 영향을 주지 않는다(§7과 합치).

트리거는 8개로, 토대 스펙이 진행 변경의 원천으로 잠근 사건들(클리어·별점·트리·옵션·환영·앱 전환·죽음)을 모두 덮는다.

추가 메모:

- 챕터 진입 직전에는 별도 저장 트리거가 없다. 진입은 단지 "마지막 진입 노드"의 메모리 상태 변경이며, 다음 트리거(클리어·앱 백그라운드 등) 시점에 함께 기록된다. 챕터 도중 추가로 저장이 발생하지 않는 이유는 토대 스펙이 잠근 "체크포인트 없음" 원칙(§7)과 정합을 맞추기 위해서다.
- 별점 갱신과 챕터 클리어가 동일 프레임에서 발생하면 한 번의 디스크 쓰기로 처리한다. 두 트리거가 별도로 적힌 것은 의미 단위 분리일 뿐, 실제 I/O는 통합된다.

## 3. 복구 정책

앱이 콜드 스타트 또는 백그라운드에서 복귀할 때, 잊혀진 자의 위치는 다음 규칙으로 결정된다.

마지막 진입 노드가 "지도"인 경우(또는 필드가 부재해 디폴트로 간주된 경우), 잊혀진 자는 지도 화면으로 복귀한다. 지도에 표시되는 노드의 해금·잠김 상태는 챕터 진행 상태·사이드 클리어 플래그에서 그대로 재구성된다.

마지막 진입 노드가 어떤 챕터를 가리키는 경우, 잊혀진 자는 **해당 챕터의 진입 룸 시작 지점**으로 복귀한다 — 챕터 도중의 좌표·HP·콤보 상태·진행한 조우 수는 모두 폐기된다. 이는 토대 스펙의 "체크포인트 없음" 원칙을 정확히 반영한다. 챕터 시작 인터루드는 일회성 환영 플래그가 이미 참인 경우 자동 건너뛰어 진입 룸으로 직접 떨어진다.

미저장 진행 손실 정책은 명시적이다. 챕터 도중 앱이 강제 종료되거나 OS가 메모리를 회수한 경우, 그 챕터의 도중 상태(처치한 잡몹 수, 이미 트리거된 다이어제틱 텍스트 등)는 전부 사라진다. 다만 "앱 백그라운드 진입" 트리거(§2)가 OS 차원에서 보장되는 한, 챕터 클리어 직후의 진행은 이미 디스크에 있다 — 사용자가 잃는 최대치는 "지금 도전 중인 한 챕터의 도중 상태"뿐이다. 한 챕터 길이가 3~5분(종장 ~7분)으로 잠겨 있으므로 손실 한도는 7분 미만의 도중 진행으로 묶인다.

초보 플레이어 복귀 가드: 챕터 도중 앱이 종료되어 진입 룸으로 돌아온 경우, **매 복귀마다 1회** 시스템 텍스트 영역에 2.5초짜리 작은 복귀 문구를 표시한다. 예: "챕터 처음부터 다시 시작. 이미 본 환영은 건너뜀." 이 문구는 다이어제틱 환경 텍스트의 하단 중앙 안전선이 아니라 결과 화면·설정 화면과 같은 시스템 알림 영역에서만 표시된다. 세이브 손실이 아니라 체크포인트 없음 정책의 결과임을 알려 주는 안내이며, 진행 축 필드에는 영향을 주지 않고 별도 저장 트리거도 만들지 않는다.

## 4. 갱신 정책

각 필드 종류는 갱신 시 다음 규칙을 따른다. 모든 규칙의 공통 정신은 "획득한 진행은 사라지지 않는다"다.

- **챕터 진행 상태 / 사이드 클리어 플래그 / 게이팅 보스 클리어 플래그**: 한 번 참으로 전환된 boolean은 절대 거짓으로 돌아가지 않는다. 트리 리셋·재도전·사망·나가기 모두 영향 없음.
- **챕터별 별점 3개**: 같은 챕터의 같은 별점 항목이 다시 클리어되어도 이미 참인 값은 거짓으로 돌아가지 않는다 — 즉 한 번이라도 획득한 별점은 영구히 보존된다.
- **SP 합계**: 누적이다. 챕터 클리어·별점 신규 획득·사이드 도전 보너스 시점마다 더해지며 줄어들지 않는다. 트리 리셋도 SP 합계를 건드리지 않는다.
- **사용 SP**: 트리 노드 구매 시 노드 비용만큼 증가, 트리 리셋 시 0으로 환원. 그 외 변경 없음. 보유 SP(=누적 SP - 사용 SP)는 항상 0 이상으로 유지되며, 0 이상이 아니게 만드는 노드 구매는 UI 단계에서 차단된다.
- **보유 스킬 노드 집합**: 노드 구매 시 해당 식별자가 추가되어 집합의 합집합이 갱신된다. 트리 리셋 시 공집합으로 환원. 노드 단위 환불·부분 리셋은 시즌 1에서 지원하지 않는다.
- **일회성 환영 플래그**: 한 번 참이면 영구히 참. 시청을 다시 강제하지 않는다.
- **트리 리셋 횟수 누적**: 단조 증가. 줄지 않는다.
- **일회성 사망 통계 (옵션)**: 챕터별로 사망마다 1 증가. 줄지 않는다. 옵션이 비활성에서 활성으로 전환된 시점부터의 카운트만 기록되며, 과거 사망은 0으로 간주.
- **입력 임계값 사용자 옵션 값**: 마지막 변경값으로 덮어씀. 누적·OR 의미가 없다.
- **마지막 진입 노드**: 마지막 변경값으로 덮어씀. 누적 의미 없음.
- **앱 버전 / 스키마 버전**: 마지막으로 세이브를 작성한 앱 버전·스키마 버전으로 덮어씀. 마이그레이션(§6)이 끝난 직후에는 새 버전으로 갱신된 후 디스크 반영.

요약하면, 진행 축(챕터·별점·SP·노드·환영·게이팅)은 모두 단조 누적이고, 환경 축(옵션·마지막 진입 노드·버전 메타)은 마지막 값 덮어쓰기다. 트리 리셋만이 예외적으로 사용 SP와 보유 노드 집합을 0/공집합으로 되돌리지만, 누적 SP·진행·별점·게이팅은 손대지 않는다.

## 5. 충돌 정책

**시즌 1은 로컬 전용(local-only) 세이브로 운용한다.** 이는 명시적 결정이며, 클라우드 동기화·다중 디바이스·계정 시스템은 시즌 1 범위 외다(토대 스펙 §"범위 외" 항목과 합치 — 시즌 1은 단일 플레이어·단일 디바이스 흐름).

이 결정의 함의:

- 디바이스 변경 시 세이브 이전을 위한 자동 메커니즘은 시즌 1에 없다. 사용자에게 이 사실을 옵션 화면 한 줄로 안내한다.
- 같은 디바이스에서 앱을 재설치하면 OS 정책에 따라 세이브가 보존되거나 사라질 수 있다. 본 문서는 OS의 앱 데이터 보존 정책을 신뢰한다 — iOS·Android 둘 다 표준 앱 컨테이너 안의 영속 저장소를 사용한다는 가정.
- 동일 디바이스 안에서의 동시 쓰기 충돌은 발생하지 않는다(앱은 단일 인스턴스 가정). 따라서 충돌 해결 알고리즘 자체가 필요 없다.

시즌 2 이후 클라우드 동기화가 도입된다면, 그때 본 문서를 갱신해 다음 형태의 정책을 추가한다 — "서버 권위, 로컬 즉시 반영 후 서버 응답 시 정정". 시즌 1 시점에는 그 절을 비워 둔다.

## 6. 마이그레이션 정책

스키마 버전 필드(§1)가 마이그레이션의 근간이다. 앱 버전과 스키마 버전이 분리되어 있어, 스키마가 바뀌지 않는 패치 릴리스에서는 마이그레이션이 발생하지 않는다.

세 가지 시나리오가 있다.

**(가) 신버전 앱이 구버전 세이브를 읽을 때** (스키마 버전 N+1 앱이 스키마 버전 N 세이브를 만남): 누락된 필드에 대해 다음 기본값 정책을 적용한다.

- 새로 추가된 boolean 매핑(예: 새 챕터의 진행 상태, 새 사이드 클리어 플래그, 새 환영 플래그) → 모든 키를 거짓으로 채운다.
- 새로 추가된 정수 필드(예: 새 카운터, 새 누적 통계) → 0으로 채운다.
- 새로 추가된 옵션 필드(예: 새 입력 옵션 키) → 디폴트 프리셋으로 채운다.
- 새로 추가된 식별자 매핑이 기존 필드와 의미적으로 겹치는 경우(예: 별점 슬롯 추가) → 기존 필드의 의미를 보존하는 변환 규칙을 마이그레이션 노트에 한 줄로 적고 적용한다. 추정·짐작 변환은 금지 — 의미가 모호하면 거부 정책으로 우회한다.

마이그레이션 후에는 스키마 버전 필드를 N+1로 갱신하고 디스크에 즉시 반영한다.

**(나) 구버전 앱이 신버전 세이브를 읽을 때** (스키마 버전 N 앱이 스키마 버전 N+1 세이브를 만남): 거부한다. 구버전 앱은 신버전 세이브의 필드를 안전하게 무시할 수 없다(누적 의미·OR 의미를 망가뜨릴 위험). 거부 시 사용자에게 다음을 보여 준다.

- "최신 버전의 앱이 필요합니다."라는 안내 한 줄.
- 앱스토어로 이동하는 버튼 한 개.
- 게임 진행 화면 진입은 차단된다(지도·트리·옵션 모두 잠김). 옵션 중 "삭제하고 새로 시작"만 활성화되어, 사용자가 의도적으로 세이브를 비우면 신규 게임으로 진입 가능.

**(다) 호환 깨짐 — 마이그레이션 변환이 모호하거나 데이터가 손상된 경우**: 마이그레이션을 시도하지 않는다. 사용자에게 다음을 보여 준다.

- "이 세이브는 현재 앱 버전과 호환되지 않습니다."라는 안내 한 단락.
- 손상의 위치를 가리키는 보조 한 줄(예: "스킬 노드 데이터를 읽을 수 없습니다.").
- 두 버튼: "백업 후 새로 시작" / "그대로 유지하고 종료". "그대로 유지"는 세이브 파일을 건드리지 않은 채 앱을 종료한다 — 이후 신버전 앱이 출시되어 마이그레이션 경로가 추가되었을 때 회수 가능성을 남긴다.

마이그레이션 정책은 보수적이다. 누적·OR 의미를 망가뜨릴 가능성이 조금이라도 있으면 거부 + 사용자 확인 경로로 우회한다. 잊혀진 자가 한 시즌 동안 모은 별점·SP·기억은 마이그레이션 한 번의 짐작으로 사라지지 않는다.

## 7. 막힌 챕터 출구 보장 정합성

토대 스펙 §"별점 도전 + 실패 처리"의 단언 — "막힌 챕터에서 빠져나갈 출구는 항상 보장된다" — 와 본 데이터 모델의 합치는 다음 한 단락으로 명시된다. 잊혀진 자가 어떤 챕터에서 사망하면 모달이 "재도전 / 나가기" 두 선택지를 띄운다. 어느 선택을 하든 §1의 진행 축 필드(챕터 진행 상태·별점·SP 합계·보유 스킬 노드 집합·게이팅 보스 클리어 플래그·사이드 클리어 플래그·일회성 환영 플래그·트리 리셋 횟수 누적·일회성 사망 통계)는 손실되지 않는다 — "나가기" 선택은 단지 마지막 진입 노드를 "지도"로 환원할 뿐이며(§2의 "사망 모달의 '나가기' 선택" 트리거), 이미 디스크에 적힌 모든 진행은 그대로 보존된다. 챕터 도중에 추가로 발생할 수 있었던 "도중 상태"(처치한 잡몹·트리거된 다이어제틱 텍스트)만이 사라지지만, 이는 체크포인트 부재 정책 자체이며 토대 스펙이 명시적으로 받아들인 손실 한도다. 따라서 **죽음 모달에서 "나가기"를 선택하는 행위는 잊혀진 자의 누적 진행을 한 점도 잃지 않으며, 막힌 챕터에서 빠져나가는 출구를 데이터 모델 차원에서 항상 보장한다.**

## 8. 챕터 1 시뮬레이션

본 절은 챕터 1 한 회 플레이를 시간 순서로 추적하며, 각 시점에 어떤 필드가 어떻게 갱신되는지를 명시한다. 사망/나가기 분기도 함께 다룬다. 시간 좌표는 챕터 1 페이싱 문서(`docs/superpowers/specs/2026-05-07-chapter-1-encounter-pacing.md`) §5의 표준 플레이 합산을 따른다.

### 8.1 시나리오 A — 표준 플레이 정상 클리어 (별점 1개 획득)

초기 상태(앱 첫 실행 후 처음 챕터 1에 진입하는 잊혀진 자):

- 챕터 진행 상태: 모두 미클리어. 별점: 모두 미획득. SP 합계: 0. 사용 SP: 0. 보유 스킬 노드 집합: 공집합. 게이팅 보스 클리어 플래그: 모두 미통과. 사이드 클리어 플래그: 모두 미클리어. 일회성 환영 플래그: 모두 미시청. 트리 리셋 횟수 누적: 0. 마지막 진입 노드: "지도". 입력 옵션: 디폴트.

이 상태로 잊혀진 자가 지도에서 본편 1을 탭하면 시간 추적이 시작된다.

- **t = -2초** — 챕터 시작 인터루드 표시. 일러스트 1장 + 텍스트 1페이지. 시청 종료 시점에 일회성 환영 플래그 "챕터 1 시작 인터루드"가 참으로 전환되고 디스크 기록(저장 트리거 §2 "일회성 환영 시청"). 이 시점에 마지막 진입 노드도 "본편 1"로 갱신되어 함께 기록된다.
- **t = 0초** — 진입 룸 페이드인. 다이어제틱 텍스트 "*이곳은 너의 자리였다.*" 트리거. 시청 종료 시 일회성 환영 플래그 갱신·디스크 기록. 이후 잊혀진 자가 진입 룸 출구 직전에 도달하면 "*너는 걸을 줄 안다.*" 트리거·기록.
- **t = 6초** — 조우 1 룸 진입. 잡몹 처치는 메모리 상태이며 디스크에 적히지 않는다(체크포인트 없음 원칙). 별점 임시 추적 — 누적 피해 카운터·경과 시간 카운터·콤보 카운터는 메모리에서만 굴러간다.
- **t = 48초** — 조우 1 두 마리 처치. "*너는 칠 줄 안다.*" 트리거·기록(일회성 환영). 누적 피해는 0(완벽 플레이) 또는 5(표준 플레이) — 메모리.
- **t = 66초** — 짧은 통로 통과. "*너는 피할 줄 알았다.*" 트리거·기록(일회성 환영).
- **t = 118초** — 조우 2 클리어. 작은 수호자 회피 성공 시 누적 피해 5 유지(메모리), 회피 실패 시 12.
- **t = 128초** — 보스 룸 진입. "*잊은 손이 기억해낸다.*" 트리거·기록(일회성 환영).
- **t = 228초** — 보스 처치. 회상 컷·결말 비트로 진입. 이 시점에 별점 확정이 일어난다.
  - 시간 별점: 240초 이내 클리어 — 본 시점이 t = 228초이므로 획득.
  - 피해 별점: 누적 피해 30 이하 — 표준 플레이 끝자락(보스 25 + 잡몹 5 = 30)이면 획득, 회피 실패가 한 번 섞여 37이면 미획득. 시뮬레이션의 "시나리오 A"는 회피 1회 늦음 가정이라 미획득.
  - 콤보 별점: 보스에게 8콤보 이상 한 번 — 첫 플레이에서는 보통 미획득.
- **t = 240초** — 결말 비트 종료. 다음 트리거가 한꺼번에 발생한다(저장 트리거 §2 "챕터 클리어" + "별점 갱신"가 합쳐진 단일 디스크 쓰기):
  - 챕터 진행 상태: 본편 1 = 클리어.
  - 챕터별 별점 3개: 본편 1의 시간 슬롯 = 획득(피해·콤보 미획득).
  - SP 합계: 0 → 2 (본편 1 클리어 +1 SP, 시간 별점 +1 SP).
  - 사용 SP: 0 (변화 없음).
  - 보유 스킬 노드 집합: 공집합 (변화 없음).
  - 게이팅 보스 클리어 플래그: 변화 없음(챕터 1은 게이팅이 아님).
  - 사이드 클리어 플래그: 변화 없음.
  - 일회성 환영 플래그: "챕터 1 종료 다리" 시청 추가.
  - 마지막 진입 노드: "본편 1" → "지도".
  - 트리 리셋 횟수 누적·일회성 사망 통계·입력 옵션: 변화 없음.
  - 앱 버전·스키마 버전: 현재 값으로 갱신(보통 변화 없음).

이후 잊혀진 자가 트리 화면을 열어 "잊은 손의 첫 박자"(콤보 가지 루트, SP 1)를 구매하면, 저장 트리거 "트리 노드 구매"가 발생해 보유 스킬 노드 집합에 해당 노드 식별자 추가, 사용 SP 0 → 1, 디스크 기록.

### 8.2 시나리오 B — 보스에서 사망, "나가기" 선택

초기 상태는 시나리오 A와 동일.

- **t = 0초 ~ t = 138초** — 시나리오 A와 동일. 진입 룸·조우 1·짧은 통로·조우 2·보스 룸 진입을 거치며 일회성 환영 플래그 5건이 차례로 디스크에 적힌다.
- **t = 138초** — 보스전 페이즈 1 도중. 텔레그래프를 두 번 놓쳐 잊혀진 자가 사망.
- **t = 138.5초** — 사망 모달 표시. 두 선택지 — 재도전 / 나가기.
- **t = 142초** — 잊혀진 자가 "나가기"를 선택. 저장 트리거 §2 "사망 모달의 '나가기' 선택" 발생.
  - 챕터 진행 상태·별점·SP 합계·보유 스킬 노드 집합·게이팅 보스 플래그·사이드 플래그·일회성 환영 플래그·트리 리셋 횟수 누적·입력 옵션: **변화 없음**. 진행은 한 점도 잃지 않는다.
  - 마지막 진입 노드: "본편 1" → "지도".
  - 일회성 사망 통계 (옵션 활성 시): 본편 1 카운트 0 → 1.
  - 디스크 기록.

이 시나리오에서 잊혀진 자는 진입 인터루드·다이어제틱 텍스트 5건을 시청한 사실은 그대로 보존하되, 챕터 자체는 미클리어 상태로 지도에 돌아온다. 다음에 본편 1을 다시 탭하면 시작 인터루드는 일회성 환영 플래그가 참이므로 자동 건너뛰어 진입 룸으로 직접 떨어진다(§3의 복구 정책과 합치). 토대 스펙의 "막힌 챕터에서 빠져나갈 출구는 항상 보장" 원칙이 데이터 차원에서 정확히 구현된다(§7).

### 8.3 시나리오 C — 클리어 후 재도전으로 추가 별점 획득

시나리오 A 직후 상태에서 시작. 챕터 1: 클리어, 시간 별점만 획득. SP 합계: 2. 보유 노드: "잊은 손의 첫 박자". 사용 SP: 1.

- **t = 0초** — 잊혀진 자가 본편 1을 다시 탭. 시작 인터루드는 일회성 환영 플래그가 참이라 자동 건너뜀.
- **t = 0초 ~ t = 240초** — 페이싱 동일. 이번에는 "잊은 손의 첫 박자" 노드 효과로 콤보 1단의 발동 창이 늘어나 보스에게 8콤보를 한 번 잇는 데 성공. 누적 피해는 25(완벽한 잡몹 회피 + 보스 25)로 30 이하.
- **t = 240초** — 결말 비트 종료. 저장 트리거 발생.
  - 챕터 진행 상태: 변화 없음(이미 클리어).
  - 챕터별 별점 3개: 본편 1의 피해 슬롯 거짓 → 참, 콤보 슬롯 거짓 → 참. 시간 슬롯은 이미 참이라 변화 없음(갱신 규칙 "기존 OR 신규" §4와 합치).
  - SP 합계: 2 → 4 (피해 별점 +1, 콤보 별점 +1; 챕터 클리어 SP는 이미 가산되어 있어 중복 가산 없음 — 챕터 클리어 트리거의 가산은 "챕터 진행 상태가 거짓에서 참으로 전환되는 순간"에만 적용됨).
  - 마지막 진입 노드: "본편 1" → "지도".
  - 디스크 기록.

본편 1은 본편당 최대 4 SP의 천장(클리어 1 + 별점 3 = 4)에 정확히 도달했다.

### 8.4 시나리오 D — 트리 리셋

시나리오 C 직후 상태. SP 합계: 4. 사용 SP: 1. 보유 노드: "잊은 손의 첫 박자".

- 잊혀진 자가 트리 화면의 리셋 모달에서 "되돌린다"를 선택. 저장 트리거 §2 "트리 리셋" 발생.
  - 보유 스킬 노드 집합: {잊은 손의 첫 박자} → 공집합.
  - 사용 SP: 1 → 0.
  - 트리 리셋 횟수 누적: 0 → 1.
  - SP 합계·챕터 진행 상태·별점·게이팅 보스 클리어 플래그·사이드 클리어 플래그·일회성 환영 플래그·일회성 사망 통계·입력 옵션·마지막 진입 노드: 변화 없음.
  - 디스크 기록.

리셋 후 잊혀진 자는 보유 SP 4를 손에 쥔 채 다른 가지의 노드 구매를 자유롭게 선택할 수 있다. 갱신 정책(§4)의 "단조 누적"과 "트리 리셋의 예외적 환원"이 함께 작동하는 정확한 사례다.

### 8.5 시나리오 E — 챕터 도중 앱 백그라운드 진입

시나리오 A의 t = 100초 시점(조우 2 룸 도중)에서 OS가 앱을 백그라운드로 보냄. 저장 트리거 §2 "앱 백그라운드 진입" 발생.

- 마지막 진입 노드: "본편 1"로 갱신(이미 그 값이라 변화 없음, 디스크 기록은 발생).
- 그 외 진행 축 필드: 변화 없음(챕터 도중 처치한 잡몹·받은 피해는 메모리에만 있음).
- 디스크 기록.

이후 잊혀진 자가 앱을 다시 열면 §3의 복구 정책에 따라 본편 1의 진입 룸 시작 지점으로 떨어진다. 도중에 처치한 잡몹·트리거된 다이어제틱 텍스트("*너는 칠 줄 안다.*" 등)의 일회성 환영 플래그는 이미 디스크에 적혀 있으므로 다시 표시되지 않는다 — 챕터를 처음부터 도는 인상은 유지하되, 환영 시청은 한 번만의 약속을 지킨다.

## 9. 자체 검토

- 저장 필드 14개로 ≥ 10 충족. 모든 필드에 의미·타입·예시 값 채워짐.

- 챕터 1 시뮬레이션이 시간 순서로 추적 가능 — 5개 시나리오, 각각 분 단위 시간 좌표와 필드 갱신을 명시.
- 토대 잠긴 어휘만 사용. "스타"·"점수" 같은 동의어 없음. 별점·SP·콤보·회피·신성·게이팅·잊혀진 자 표기 일관.
- 트리 노드 보유는 "식별자 집합"으로 텍스트 기술. 코드 없음.
